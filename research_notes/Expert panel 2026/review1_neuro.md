# Test 1 review — Neuroscientist
Verdict: worth running only with changes to the personal arm. A2, Part B, bookkeeping sound. Personal arm close to a certain pass; forecast 27B think as written: same and reword >= 92% at 5,000, two-hop ratio >= 0.9, stale <= 5% (~80% confidence). A test callable at ~80% that licenses a big decision gives little information.
Every question carries the unique full name verbatim in every relevant note → find a string, pick 1 of ~4 notes by answer type.
Flaws:
1. Reword doesn't break encoding specificity (name always matches; answer type picks the note). Fix: described-person questions ("What pet does the nurse who lives in Porto have?", script checks pair unique incl. after updates) + first-name-only with disambiguator ("Paula, the one who plays the mandolin"). ~120 q, ~40 lines.
2. No fan, no lures. Fix: ~30 "close" people with ~40 notes each incl. same-attribute lures ("test-drove a Kia", "used to live in Porto", "is visiting Lyon this week", "her brother drives a Volvo"); drop groups to keep ~5,000; 90 questions vs few-fact people. Perfect person selection returns 40+ notes for them → selected-pages no longer an upper bound for the people who matter most.
3. Updates flagged by wording, single. Job Q shares words with new note; city Q with old note → report stale by attribute. Fix: half the updates in original form ("Matteo Lopes works as a locksmith.") so only order distinguishes; 30 people with three successive values (AB-AC-AD); drop "now" from half; 20 "before" questions. ~60 q.
4. Two-hop matches a note word for word ("Signe Larsen's neighbour"). Fix: half relation notes reversed/symmetric ("Bilal Barbosa lives next door to Signe Larsen"; "X rents a flat from Y"); A gets 2–3 relations.
5. Decision set on the easy case. Make v1 depend on hard conditions: at 5,000 ≥ 0.8 of their own selected-pages accuracy; keep current lines as easy reference. Predictions hard at 5,000: described-person 60–80%; close people with lures 10–20 pts below few-fact; same-form repeated updates 10–25% stale.
6. Classify every wrong answer's source (no model calls): same first/last name person, other person in group, lure, old value, adjacent note, made up.
Cost: separate Part A3 so A stays stub-tested; run A3 at 5,000 and selected-pages, thinking on, right after 27B think 5,000/10. ~600 extra calls per model on cached pile, ~30–45 min per model.
Link to test 3: same world generator; fan factor = factorial's richness manipulation (bridges with 0/8/32 extra notes, two-hop through them). In context fan effect predicts richness hurts; in weights H1 predicts helps. Same items → clean denominator (in-context accuracy on identical items) and possibly the two-system signature. Error labels carry over.
