# Frontier labs on memory, continual learning, personalization & long-horizon agents: what is shipped vs. admitted limits (2024 – 29 Sep 2026)

(Working notes, written incrementally. Status: COMPLETE (29 Sep 2026). Dates are publication/announcement dates as given by the source. "UNVERIFIED" = could not confirm from a primary source.)

## Q1. What do deployed "memory"/"learning" features actually do mechanically? (lab by lab)

### Takeaway
As of 29 Sep 2026, every shipped "memory" feature at OpenAI, Anthropic, Google, Meta and xAI is external text memory put back into the model's context — (a) short model-written summaries/notes/entries injected into the prompt (ChatGPT saved memories + chat-history "dossier", ChatGPT Dreaming, Codex memory_summary.md capped at 2,500 tokens, Claude memory summary/entries, Claude Code CLAUDE.md + MEMORY.md first 200 lines/25KB) and/or (b) retrieval via tool calls/RAG (Claude chat search, Gemini Personal Intelligence "context packing", Claude memory tool, Managed Agents memory stores). The 2025–26 "dreaming" features from both OpenAI and Anthropic are offline LLM consolidation passes that rewrite that text store; no official documentation describes per-user fine-tuned adapters or post-deployment weight updates.

#### OpenAI — Codex memories (2026) — verified in open-source code
- Codex "Memories" (preview, 2026; off by default; Enterprise/Edu first; EU/UK delayed per secondary sources): remembers "stable preferences, recurring workflows, tech stacks, project conventions, and known pitfalls"; "skips active or short-lived sessions, redacts secrets ... and updates memories in the background". — [OpenAI Codex docs, "Memories"](https://developers.openai.com/codex/memories) (blocked here; via search extract); [GitHub discussion openai/codex #12567](https://github.com/openai/codex/discussions/12567)
- Mechanism, verified from the openai/codex repo (main branch as of 29 Sep 2026): a background two-phase pipeline triggered at session start. Phase 1 sends recent idle rollouts (session transcripts) "to a model" which returns structured `raw_memory` + `rollout_summary`, with secrets redacted, stored in a local state DB. Phase 2 "Global Consolidation" writes `raw_memories.md` and `rollout_summaries/` under `~/.codex/memories/` (git-baselined), ranks memories by `usage_count`/recency and drops ones unused beyond `max_unused_days`, then spawns "an internal consolidation sub-agent" (no network, local write only) to update the memory files. Read path: `memory_summary.md` is read and injected into the model's developer instructions, truncated at `MEMORY_TOOL_DEVELOPER_INSTRUCTIONS_SUMMARY_TOKEN_LIMIT` = 2,500 tokens (a secondary April 2026 write-up cited 5,000 — the limit has changed over versions). — [openai/codex codex-rs/memories/README.md](https://github.com/openai/codex/blob/main/codex-rs/memories/README.md); [openai/codex codex-rs/ext/memories/src/lib.rs & prompts.rs](https://github.com/openai/codex/blob/main/codex-rs/ext/memories/src/prompts.rs); older limit: [Codex Knowledge Base, 8 Apr 2026](https://codex.danielvaughan.com/2026/04/08/codex-cli-memory-internals/)
- This is the closest inspectable analogue of ChatGPT "dreaming": an offline LLM "consolidation" pass that rewrites a text memory store, with usage-based forgetting; the model's weights are untouched.

- Legacy mechanism (help center): "Claude will automatically summarize your conversations and create a synthesis of key insights across your chat history... This synthesis is updated every 24 hours." New (2026) mechanism: Claude "saves memory as a set of individual topics as you chat, rather than summarizing conversations after they end"; memory generation on by default for Free/Pro/Max, off by default for Team/Enterprise. Legacy memory export available "until September 9, 2026". — [Claude Help Center](https://support.claude.com/en/articles/11817273-using-claude-s-chat-search-and-memory-to-build-on-previous-context)
- Press: memory extended to Free plan in March 2026; memory shared across chat and Cowork sessions; on 10 Jul 2026 the single rolling summary was replaced by "individual, categorized entries that Claude reads and updates during conversations". — [MacRumors, 23 Oct 2025](https://www.macrumors.com/2025/10/23/anthropic-automatic-memory-claude/); [Engadget](https://www.engadget.com/2243753/claude-memory-now-works-across-both-chats-and-cowork-sessions/); [MemX blog](https://memx.app/blog/claude-memory-editable-entries-update/) (July 2026 date from secondary source; UNVERIFIED against an Anthropic primary)
- Claude Code (official docs, read directly 29 Sep 2026): "Each Claude Code session begins with a fresh context window. Two mechanisms carry knowledge across sessions": CLAUDE.md files (human-written) and "Auto memory: notes Claude writes itself based on your corrections and preferences". Both "are loaded at the start of every conversation. Claude treats them as context, not enforced configuration." Auto memory lives in ~/.claude/projects/<project>/memory/ with a MEMORY.md index; "The first 200 lines of MEMORY.md, or the first 25KB, whichever comes first, are loaded at the start of every conversation"; topic files are read "on demand using its standard file tools". "CLAUDE.md content is delivered as a user message after the system prompt". Auto memory is "machine-local". Memory types: user / feedback / project / reference. — [Claude Code docs, "How Claude remembers your project"](https://code.claude.com/docs/en/memory)
- Claude Developer Platform memory tool (29 Sep 2025, beta; docs read 29 Sep 2026): "The memory tool operates client-side: Claude requests file operations, and your application executes them." Claude "automatically checks its memory directory before starting a task" and "stores what it learns in files under `/memories`"; framed as "just-in-time context retrieval". — [Claude Platform docs, Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)
- Claude Managed Agents memory stores (beta header `agent-memory-2026-07-22`): "Each Managed Agents session starts with a fresh context by default. When a session ends, any state the agent built up is gone. Memory stores let the agent carry information across sessions". A memory store is "a workspace-scoped collection of text documents" mounted as a directory in the session sandbox; the agent reads/writes it with file tools; each change creates an immutable memory version; limits: 100 kB (~25k tokens) per memory, 10,000 memories per store, 8 stores per session. — [Claude Platform docs, "Using agent memory"](https://platform.claude.com/docs/en/managed-agents/memory)
- Anthropic "Dreaming" for Managed Agents (announced 19 May 2026 at Code with Claude; research preview; beta header `dreaming-2026-04-21`): "Dreaming is a scheduled process in Claude Managed Agents that reviews agent sessions and memory stores, extracts patterns, and curates memories so agents improve over time." Docs: "A dream reads an existing memory store alongside past session transcripts [1 to 100 sessions], then produces a new, reorganized memory store: duplicates merged, stale or contradicted entries replaced with the latest value, and new insights surfaced. The input store is never modified". Runs with a chosen Claude model (e.g., claude-opus-4-8, claude-opus-5, claude-sonnet-5). Customer claim: Harvey's "Completion rates went up ~6x in their tests" (Anthropic-reported, customer internal test, no methodology). — [Claude blog, "New in Claude Managed Agents: dreaming, outcomes, and multiagent orchestration" (19 May 2026)](https://claude.com/blog/new-in-claude-managed-agents); [Claude Platform docs, "Dreams"](https://platform.claude.com/docs/en/managed-agents/dreams)
- NAMING NOTE: both OpenAI (ChatGPT "dreaming", Apr 2025 v1 / Jun 2026 update) and Anthropic (Managed Agents "dreaming", May 2026) use "dreaming" for OFFLINE LLM CONSOLIDATION OF A TEXT MEMORY STORE (sleep-consolidation metaphor). Neither documentation describes gradient updates to model weights.
- Mechanism verdict: all Anthropic consumer/dev memory = plain-text files/summaries in context + RAG tool calls over past chats. No weight updates are described anywhere in the docs.

### Inferences
- The industry converged (Apr 2025 – Jul 2026) on the same three-layer design: explicit saved facts -> automatic extraction from chat history -> background "consolidation"/"dreaming" that dedups, updates stale facts and prunes by usage. This is a software approximation of hippocampal consolidation implemented entirely in text; its ceiling is bounded by context budget and retrieval quality (e.g., Codex injects at most 2,500 tokens of summary; Claude Code loads only the first 200 lines/25KB of MEMORY.md).
- OpenAI's and Anthropic's use of the word "learn" (ChatGPT dreaming "allows ChatGPT to learn from many conversations"; Claude Code "auto memory lets Claude learn from your corrections"; Managed Agents "agents improve over time") refers to memory-store curation. Report-writers should not treat these as evidence of continual learning in weights.
- Google's statement that Gemini trains on prompts/responses (but not directly on Gmail/Photos) shows the only "weights" path for user data is ordinary pooled training of future model versions — slow, population-level, and not per-user.
- The Cursor Tab/Composer online-RL loops (non-frontier) show deployment-signal-to-weights is technically feasible at the population level with hours-scale cycles; frontier labs have not publicly described an equivalent for their consumer assistants.

### Gaps
- openai.com / help.openai.com were blocked in this environment, so the June 2026 Dreaming post was read only through search-engine extracts; OpenAI's exact wording on whether Dreaming touches training data/weights, and the "Dreaming V3" label and "5x cheaper" claim (secondary sites only), remain unverified.
- The mechanics of ChatGPT's chat-history injection (section names, size limits) come from independent reverse-engineering (Simon Willison, May 2025); not confirmed from OpenAI docs in this session.
- Anthropic's 10 Jul 2026 switch from a rolling summary to categorized entries is supported by the help center ("individual topics as you chat") but the exact date comes from a secondary source (MemX).
- Meta AI (Muse Spark era, 2026) and Grok memory internals are not documented publicly beyond "view/delete memories"; no primary technical docs were reachable.
- Whether any lab internally uses per-user LoRA/adapters (e.g., for enterprise) is not public; no evidence found either way.

## Q2. Dated public statements by lab leaders/researchers on continual learning / memory as unsolved or a priority

### Takeaway
Lab leaders split into two camps. Explicit "it's missing" admissions: Demis Hassabis (Feb 2026: today's systems are "kind of frozen"; they should "continually learn online from experience... today's systems don't do that") and Ilya Sutskever (Nov 2025: target is a "superintelligent 15-year-old" that learns on the job; "age of research"). Context-first/deflationary: Sam Altman's vision of memory is "a trillion tokens of context" (May 2025), Dario Amodei (Feb 2026) suggested continual learning may not be a barrier given in-context learning over 1M-token windows plus pretraining/RL generalization, and OpenAI's Jakub Pachocki (Apr 2026) discussed "continual learning hype" and favoured large-context, prompting-based learning alongside RL. Anthropic's Sholto Douglas predicted (Dec 2025) continual learning would be "solved in a satisfying way" in 2026 — no public evidence as of Sep 2026 that it has been.

## Q3. Lab-published research on continual learning, memory layers, test-time training, learning from experience; hiring/roadmaps 2025–2026; has anyone shipped post-deployment weight learning?

### Takeaway
The most advanced LAB-PUBLISHED work on learning after deployment is still research-scale and mostly per-sequence: Google's Titans/ATLAS/MIRAS/Nested Learning-Hope (test-time-updated memory modules, ~≤1.3B-param experiments, memory reset per sequence) and Meta FAIR's Sparse Memory Finetuning (1.3B model; NaturalQuestions F1 drop 11% vs 89% full FT / 71% LoRA when learning new facts), plus recipe-level work from Thinking Machines (on-policy distillation restoring IF-eval 79%->83% after document fine-tuning while keeping new knowledge). Lab work on "learning from experience" for agents (Google's ReasoningBank, up to +34.2% relative; DeepMind's Evo-Memory; Meta MSL's Early Experience, +13 to +18 points over imitation) learns either into memory banks at test time or into weights at TRAINING time — not continuously per user after deployment. DeepSeek's Engram (Jan 2026) and Qwen3.8-Next's 51B-param off-GPU n-gram tables (Aug 2026) add large static lookup memories that could become a locus for targeted updates, but are frozen after pretraining. No frontier lab has shipped end-user post-deployment weight learning as of 29 Sep 2026; OpenAI and Anthropic have published no in-weights continual-learning method papers.

### Cited Findings

(Technical depth on Titans / ATLAS / Nested Learning-Hope / Memory Layers / Sparse Memory Finetuning / TTT-E2E is in the sibling file `continual_learning_in_weights_sota.md`; below is the lab-attribution view with dates, headline results and stated limits.)

#### Google (Research / DeepMind)
- Titans (Behrouz, Zhong, Mirrokni; arXiv 2501.00663, 31 Dec 2024): neural long-term memory module whose parameters are updated by gradient ("surprise") at TEST time within a sequence; scales to >2M-token context on needle tasks. Memory is per-sequence — nothing written back to the deployed model's slow weights across users/sessions. — [arXiv 2501.00663](https://arxiv.org/abs/2501.00663)
- ATLAS (arXiv 2505.23735, May 2025): optimizes memory over a sliding window of past tokens ("Omega rule"); authors report "+80% accuracy in 10M context length of BABILong" over Titans. — [arXiv 2505.23735](https://arxiv.org/abs/2505.23735)
- Nested Learning / "Hope" (Google Research blog 7 Nov 2025; NeurIPS 2025): reframes a model as nested multi-level optimization problems; Hope = self-modifying Titans variant + "Continuum Memory System" with modules updating at different frequencies; blog claims lower perplexity/higher accuracy than modern recurrent models and better NIAH vs Titans, Samba, TTT, Mamba2, and better continual-learning results. Scale is research-scale (hundreds of millions to ~1.3B params); not a product. — [Google Research blog, "Introducing Nested Learning: A new ML paradigm for continual learning" (7 Nov 2025)](https://research.google/blog/introducing-nested-learning-a-new-ml-paradigm-for-continual-learning/); [VentureBeat](https://venturebeat.com/ai/googles-nested-learning-paradigm-could-solve-ais-memory-and-continual)
- DeepMind position paper: David Silver & Richard Sutton, "Welcome to the Era of Experience" (Apr 2025; preprint of a chapter for MIT Press "Designing an Intelligence"): argues human-data-driven progress is "approaching a limit" and that agents should "learn continually from their own experience" in long-lived "streams" rather than short episodes. — [Silver & Sutton via Sutton's X post, Apr 2025](https://x.com/RichardSSutton/status/1910761446637719588?lang=en); [Semantic Scholar entry](https://www.semanticscholar.org/paper/Welcome-to-the-Era-of-Experience-Silver-Sutton/9b608a6c80271cc996f22f584f9da4c43e354f45)

- Nested Learning full paper: "Nested Learning: The Illusion of Deep Learning Architectures" (arXiv 2512.24695, 31 Dec 2025; Behrouz, Razaviyayn, Zhong, Mirrokni). — [arXiv 2512.24695](https://arxiv.org/abs/2512.24695)
- MIRAS, "It's All Connected: A Journey Through Test-Time Memorization, Attentional Bias, Retention, and Online Optimization" (Google; arXiv 2504.13173, 17 Apr 2025): unifying framework for test-time-memorizing sequence models (Titans family). — [arXiv 2504.13173](https://arxiv.org/abs/2504.13173)
- Independent reproduction caveat: "Titans Revisited" (Sapienza; arXiv 2510.09551, Oct 2025) re-implemented Titans (no official code) and found it "doesn't always outperform baselines due to chunking", though the neural-memory component helps vs attention-only. — [arXiv 2510.09551](https://arxiv.org/abs/2510.09551)
- ReasoningBank (Google Cloud AI Research + UIUC/Yale; arXiv 2509.25140, 29 Sep 2025): learning from experience via MEMORY, not weights — distills "generalizable reasoning strategies from an agent's self-judged successful and failed experiences", retrieves them at test time and writes new lessons back; plus memory-aware test-time scaling (MaTTS). On WebArena, Mind2Web, SWE-Bench-Verified: "up to 34.2% relative improvement" in effectiveness and "16.0% less interaction steps". Motivating admission: deployed agents "largely fail to learn from their accumulated experience across tasks... doomed to repeat past errors". — [arXiv 2509.25140 (read via HF mirror)](https://arxiv.org/abs/2509.25140)
- Evo-Memory (Google DeepMind + UIUC; arXiv 2511.20857, 25 Nov 2025): streaming benchmark for "test-time evolution, where LLMs retrieve, integrate, and update memory continuously during deployment"; implements >10 memory modules over 10 datasets; proposes ReMem (action–think–memory-refine). States: "existing LLM memory systems remain largely static... agents remember what was said but not what was learned." — [arXiv 2511.20857 (read via HF mirror)](https://arxiv.org/abs/2511.20857)

#### Meta (FAIR / Meta Superintelligence Labs)
- "Memory Layers at Scale" (FAIR, Dec 2024): trainable product-key memory layers (up to 128B memory params) replacing some FFNs; improves factual QA at fixed compute. — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- "Continual Learning via Sparse Memory Finetuning" (Jessy Lin et al., FAIR + UC Berkeley; arXiv 2510.15103, Oct 2025): update only memory slots highly accessed by new data relative to pretraining usage (TF-IDF); on learning new TriviaQA facts, held-out NaturalQuestions F1 drops 89% after full finetuning, 71% with LoRA, but only 11% with sparse memory finetuning at equal new-knowledge acquisition. Research-scale (1.3B model); not deployed. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- "Agent Learning via Early Experience" (Meta Superintelligence Labs + collaborators; arXiv 2510.08558, Oct 2025): reward-free training in which the agent branches from expert states, takes its own actions and turns resulting states into supervision (Implicit World Modeling; Self-Reflection). Reported absolute gains over imitation learning: +18.4 (WebShop), +15.0 (TravelPlanner), +13.3 (ScienceWorld); up to +6.4 final success when used to initialize RL. This is training-time learning from agent-generated experience, not post-deployment per-user learning. — [arXiv 2510.08558](https://arxiv.org/abs/2510.08558); [MarkTechPost, 15 Oct 2025](https://www.marktechpost.com/2025/10/15/meta-ais-early-experience-trains-language-agents-without-rewards-and-outperforms-imitation-learning/)

#### DeepSeek
- "Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models" (Engram; DeepSeek-AI + Peking University; arXiv 2601.07372, 12 Jan 2026; code at github.com/deepseek-ai/Engram): modernized N-gram embedding table with O(1) hashed lookup, gated into specific layers; scaled to 27B params; vs iso-param/iso-FLOPs MoE: MMLU +3.4, CMMLU +4.0, BBH +5.0, ARC-C +3.7, HumanEval +3.0, MATH +2.4; Multi-Query NIAH 84.2 -> 97.0; offloading a 100B-param table to host memory costs <3% overhead. Authors call it "static memory" for "fixed knowledge" — it is learned during pretraining, not updated after deployment; relevant to continual learning only as a potential locus for targeted updates. Ablation: disabling Engram leaves factual benchmarks at 29–44% of original (TriviaQA 29%). — [arXiv 2601.07372 (read via HF mirror)](https://arxiv.org/abs/2601.07372); [GitHub deepseek-ai/Engram](https://github.com/deepseek-ai/Engram); [Introl blog](https://introl.com/blog/deepseek-engram-conditional-memory-architecture-january-2026)

#### Moonshot (Kimi) and Alibaba (Qwen) — architecture bets relevant to memory
- Kimi Linear (Moonshot "Kimi Team"; arXiv 2510.26692, 30 Oct 2025): hybrid of Kimi Delta Attention (a delta-rule linear attention, i.e., a fixed-size "finite-state RNN memory" updated per token = in-sequence fast weights) and MLA; 48B total / 3B active; claims to outperform full MLA under identical recipe, up to 75% less KV cache and up to 6x decoding throughput at 1M context; open weights. This is long-context efficiency, not cross-session learning. — [arXiv 2510.26692](https://arxiv.org/abs/2510.26692)
- Qwen3.8-Flash-Next architecture paper (Qwen team; arXiv 2608.30320, 31 Aug 2026): 125B total / 6B active MoE with Gated DeltaNet + sparse-attention hybrid and "additional 51B parameters of n-gram embedding tables held off the accelerator" prefetched from host memory (an Engram-style static memory); notes "enlarging the n-gram vocabulary lowers loss monotonically while downstream accuracy saturates". Shows DeepSeek's Engram-style lookup memory being adopted by another Chinese lab within ~8 months — but again as pretraining-time static memory. — [arXiv 2608.30320 (metadata/abstract via HF)](https://arxiv.org/abs/2608.30320)

#### Thinking Machines Lab
- "On-Policy Distillation" (Kevin Lu et al., blog, 27 Oct 2025): explicitly pitched for "continual learning"/personalization. Experiment: mid-training an assistant on internal company documents raised internal-QA knowledge but dropped IF-eval from 85% to 79%; on-policy distillation using the EARLIER model as teacher restored IF-eval to 83% while internal-QA knowledge rose (36% -> 41%). Proposes alternating "fine-tune on new data" and "distill to recover behaviour" phases as a continual-learning recipe. Research demo, not a product that learns per user. — [Thinking Machines, "On-Policy Distillation"](https://thinkingmachines.ai/blog/on-policy-distillation/) (blocked here; numbers via search extracts, treat as needing verification); [Tinker distillation docs](https://tinker-docs.thinkingmachines.ai/cookbook/recipes/distillation/)

### Inferences
- Research is converging on "where to write" (sparse memory slots, lookup tables, fast-weight modules, LoRA-plus-distillation) as the answer to catastrophic forgetting, but none of the lab papers demonstrate the full loop needed for products: many users, safe per-user isolation, unlearning/deletion, and evaluation on frontier-scale models.
- The capability gap is visible in independent evaluation: CL-Bench (Jun 2026) finds frontier systems with dedicated memory systems fail to reuse knowledge across instances and are beaten by naive ICL — i.e., shipped memory scaffolding does not yet deliver learning-from-experience.
- Commercial pressure (privacy, deletion rights, per-user serving cost of adapters, safety of self-modifying models, memory-poisoning risks noted in Meta's Muse testing) plausibly explains why labs ship editable text memory instead of weight updates: text memory is inspectable, deletable, cheap to serve and model-version-agnostic.
- The nearest production analogue of continual learning — hours-cadence population-level RL from user signals (Cursor Tab, Cursor Composer real-time RL) — comes from an application company, suggesting the first "learning from deployment" frontier products may be population-level checkpoint refresh rather than per-user learning.
