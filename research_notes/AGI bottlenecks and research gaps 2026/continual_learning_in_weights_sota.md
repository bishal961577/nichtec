# Continual learning into model weights for LLMs & test-time / in-weights memory architectures (2024 – 29 Sep 2026)

(Working notes, written incrementally. Sources read via Hugging Face paper mirror of arXiv full text unless stated; arXiv IDs given. "UNVERIFIED" = could not confirm from primary text.)

## Q1. Memory layers (Memory Layers at Scale; Sparse Memory Finetuning; follow-ups)

### Takeaway
Memory layers (Meta, Dec 2024) swap 1–3 FFNs for a product-key lookup into up to 64M slots (128B params) and markedly improve factual QA per FLOP (1.3B base: NQ 7.76→13.68, up to 20.78 with 64M keys). Sparse Memory Finetuning (Oct 2025) exploits this sparsity: per batch it updates only the top-t memory VALUES ranked by TF-IDF (access frequency in the batch × rarity of access on 1,000 DCLM pretraining batches). On a 1.3B model this learns 1K TriviaQA facts with an 11% NaturalQuestions-F1 drop vs 71% (LoRA) and 89% (full FT). Evidence is facts-only and ≤1.3B. 2026 follow-ups retrofit memory layers into Qwen-2.5-0.5B and propose KL-divergence slot scoring; no public Meta memory-layer weights were found (code only, CC-BY-NC).

### Cited Findings

#### Sparse Memory Finetuning (SMF) — Jessy Lin, Luke Zettlemoyer, Gargi Ghosh, Wen-Tau Yih, Aram Markosyan, Vincent-Pierre Berges, Barlas Oğuz (author list per search index; FAIR at Meta + UC Berkeley); arXiv 2510.15103 (v1 dated 16 Oct 2025, posted 20 Oct 2025)
- Headline: "while NaturalQuestions F1 drops by 89% after full finetuning on new facts and 71% with LoRA, sparse memory finetuning yields only an 11% drop with the same level of new knowledge acquisition" (setting: learning a stream of 1K TriviaQA facts; held-out = NaturalQuestions F1) — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Mechanism: memory layer replaces ONE FFN in the middle of the transformer (layer 12 of 22) with a product-key lookup into a pool of 1M slots, k=32 accesses per token, 4 memory heads, value dim 1024 → "32∗1024=32,768 active parameters in this layer instead of 50M parameters in original FFN (model dim 2048, FFN dim 2048∗4)". Output = (y ⊙ silu(xᵀW1))ᵀW2 input-dependent gating; keys/values are trainable parameters. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Base model: 1.3B-parameter model pretrained from scratch (same data for all methods); batch size 64; seq len 64 (TriviaQA) / 512 (SimpleQA). — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- HOW SLOTS ARE CHOSEN: per batch, count all memory-index accesses; rank each slot with TF-IDF where TF = the slot's share of accesses in the current batch and IDF = log((|B|+1)/(#background batches in which slot is accessed +1)); background B = memory accesses on 1000 random batches of DCLM (proxy for pretraining data). "These 'background indices' do not change during finetuning and can be stored statically in the model checkpoint." Only the VALUES of the top-t slots receive gradient (stop-gradient on all other memory params); all accessed slots still contribute to the forward pass. Ranking is batch-level, so no task-boundary assumption. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- So: slot choice = "TF-IDF relative to pretraining usage" — both notions in the question are the same mechanism (TF = access in the new batch; IDF = rarity of access on pretraining/DCLM background). — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- t values: t=500 sufficient for fact learning; t=10,000 for document QA. Each forward pass accesses 10^3–10^6 indices (k × heads × batch × seqlen). Sweep t ∈ {25,50,100,200,500,1000}, lr ∈ {0.1, 2}; main results report lr=5 (high) and lr=2 (low). — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Optimizer matters: SGD used for SMF; AdamW (λ=0.1) best for full-FT and LoRA baselines; authors note Adam's adaptive per-parameter steps, weight decay and momentum "interact with sparsity in unexpected ways"; switching to SGD reduced SMF forgetting further but did not help FT/LoRA. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- What was learned: (1) Fact learning: 1K TriviaQA test questions rephrased as statements, each fact's batch filled with N paraphrases, one immediate gradient step per fact, in sequence; held-out = NaturalQuestions F1, HellaSwag acc, GSM8K NLL. (2) Document QA: 100 Wikipedia-grounded SimpleQA questions → cited Wikipedia docs split into 1,824 paragraph chunks, streamed one chunk at a time, each batch = N "Active Reading" synthetic augmentations of the same chunk. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Ablations: naive finetuning of all accessed memory values still causes catastrophic forgetting; full-finetuning the memory model (lr 5e-6) → final GSM8K NLL 3.87 (outlier); TF-only ranking learns comparably but forgets more, gap wider at t=50; using TriviaQA itself as background → more forgetting; NQ as background ≈ DCLM. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Mechanistic analysis: "core set" (indices shared by all paraphrases and the question) typically 100–500 indices; trainable indices align with core set and "often align with entity boundaries". — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Pareto sweep: full-FT lr {2e-6,5e-6,2e-5,5e-5} (lr >5e-6 "break" the model); LoRA rank {32,128,256}, alpha {½,1,2,4}×rank, lr {2e-4,5e-5,5e-6}; "sparse memory finetuning indeed Pareto dominates, learning more while forgetting less." — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Stated limitations/future work: tested only on factual learning "for which RAG is a natural present-day solution"; need "to scale our results to more complex tasks beyond fact learning, as well as larger models"; better slot-selection (input-dependent t, other reranking criteria); optimizer choice for CL unexplored. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)


#### Memory Layers at Scale — Vincent-Pierre Berges, Barlas Oğuz, Daniel Haziza, Wen-tau Yih, Luke Zettlemoyer, Gargi Ghosh (Meta FAIR); arXiv 2412.09764 (v2 dated 20 Dec 2024)
- Design: trainable key-value lookup replacing the FFN of one or more transformer layers; trainable product-quantized keys (Lample et al. 2019: two half-key sets of size √N, top-k over the product); shared memory pool across all memory layers; "Memory+" = 3 memory layers (centred, stride 4 for 134m, 8 for others), swilu/silu input-dependent gating output=(y⊙silu(xᵀW1))ᵀW2, key dim = half value dim; qk-norm for stability. — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Systems: memory values sharded across embedding dim across GPUs; custom CUDA EmbeddingBag kernels reach "3TB/s of memory bandwidth, close to H100 spec 3.35TB/s (vs <400GB/s with PyTorch)"; "end-to-end 6x faster compared to PyTorch's EmbeddingBag". Memory layers are "almost entirely memory bandwidth bound". — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Scale: base models 134M, 373M, 720M, 1.3B (Llama2 tokenizer, trained to 1T tokens) and 8B (Llama3 config); memory up to 64M keys = "128B memory parameters"; 8B base + 4096² (=16M) memory values = 64B extra params trained to 200B and 1T tokens. — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Results (Table 1, 1M memory values unless noted; NQ accuracy / TQA F1): 1.3B dense 7.76 / 32.64; 1.3B Memory 9.83 / 39.47; 1.3B Memory+ (3.377B total) 13.68 / 42.89; Memory+ 4M (9.823B total) 14.43 / 51.18; Memory+ 16M (35.618B) 20.14 / 58.67; Memory+ 64M (138.748B total) 20.78 / 62.14; vs Llama2 7B (2T tokens) 25.10 / 64.00. MOE at 1.3B (3.545B total) 8.14 / 31.46 — MoE "underperform[s] the memory variants by large margins". — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Claims: memory models "outperform dense models with more than twice the computation budget"; "improve factual accuracy... by over 100%"; 1.3B with 64M keys "approaches the performance of the Llama2 7B model, trained on 2x more tokens using 10x more FLOPs"; at 8B, "At only 1 trillion tokens of training, our Memory+ model approaches the performance of Llama3.1 8B, which was trained on 15 trillion tokens" (8B table numbers were rendered as image in mirror – not captured). Gains larger early in training (200B tokens) → "memory helps models learn facts faster". — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Ablations: ~3 memory layers is the sweet spot (more replaces too many dense FFNs, degrading); value dim = model dim optimal. — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Stated shortcomings: "substantial engineering task to make them efficient enough for large scale production uses"; only "high level empirical evidence" on factuality (short-form QA only; long-form left to future work); hopes sparse updates enable "less forgetting, fewer hallucinations, and continual learning" (i.e. CL was not tested in this paper). — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)

#### 2026 follow-ups on sparse memory finetuning (full text NOT readable here — arXiv/bytez/pith/awesomepapers blocked by proxy; details below are from search-engine abstracts/snippets only, flag as partially verified)
- "Improving Sparse Memory Finetuning" — Satyam Goyal, Anirudh Kanchi, Garv Shah, Prakhar Gupta; arXiv 2604.05248, submitted 6 Apr 2026. Contributions per abstract: (1) open-source "retrofitting" pipeline that surgically replaces FFNs in a pretrained Qwen-2.5-0.5B with sparse key-value memory layers followed by a "healing" stage to recover general capability; (2) critiques TF-IDF and proposes a KL-divergence slot-scoring rule "based on the information gain of the current batch relative to a background usage distribution" (prioritising "informationally 'surprising'" slots); (3) retrofitted models learn TriviaQA via sparse updates "while maintaining higher stability on held-out benchmarks (GSM8k, NaturalQuestions) compared to dense finetuning". Exact numbers not obtained. — [arXiv 2604.05248](https://arxiv.org/abs/2604.05248)
- "Sparse Memory Finetuning as a Low-Forgetting Alternative to LoRA and Full Finetuning" — arXiv 2605.03229 (v2 exists; search snippets date it to May/June 2026; Prakhar Gupta among authors). Re-implements SMF on Qwen-2.5-0.5B-Instruct; task = MedMCQA (4-choice medical exam); forgetting probes = WikiText perplexity and TriviaQA accuracy. "SMF improves MedMCQA by 2.5 percentage points while keeping both forgetting probes within roughly 1 point of the base model, whereas LoRA and full finetuning achieve larger gains but with clear drift on both." Compares KL-divergence vs TF-IDF row selection, which "balance the two forgetting metrics differently". — [arXiv 2605.03229](https://arxiv.org/abs/2605.03229)
- Note: both follow-ups are small-scale (0.5B) academic replications; they illustrate SMF's main weakness: lower plasticity on a skill-like task (MedMCQA +2.5 pp, less than LoRA/full FT). — inference from [arXiv 2605.03229](https://arxiv.org/abs/2605.03229)

### Inferences (Q1)
- SMF is the cleanest published evidence (as of Sep 2026) that *where* you write matters more than *how much* you write: the same learning on TriviaQA facts with ~11% vs 71–89% held-out degradation. But the evidence is (a) at 1.3B scale, (b) on fact recall only, (c) on a model pretrained from scratch with a memory layer — no frontier-scale memory-layer model with public weights exists, so replication has been at 0.5B via retrofitting.
- The TF-IDF IDF term is essentially a cheap, static "importance" prior (akin to a sparse, binary EWC/Fisher mask computed on pretraining data). 2026 follow-ups replace it with KL/information-gain scoring; no follow-up has yet demonstrated SMF on skills (coding, reasoning) at scale.

### Gaps (Q1)
- Exact numbers of the 2026 SMF follow-ups (2604.05248, 2605.03229) could not be read (arXiv, bytez, pith, awesomepapers, lacuna, openreview blocked; not on HF papers mirror). Only abstract-level claims recorded.
- Memory Layers at Scale 8B table values (Table 2) were rendered as an image in the mirror — not captured.
- No evidence found that Meta (or anyone) has deployed memory layers in a production LLM (Llama 4 is MoE, not memory-layer) — not verified either way.

## Q2. Test-time training / learned memory architectures (TTT, Titans, ATLAS, Nested Learning/Hope, linear attention as memory, fast weights)

### Takeaway
TTT layers, Titans, ATLAS, Hope and TTT-E2E all learn a per-sequence associative/next-token model in fast weights at inference time. This improves long-context perplexity and latency (TTT-E2E 3B: tracks full-attention scaling to 128K at 2.7× lower latency). But recall is lossy (full attention 'dramatically outperforms' TTT-E2E on NIAH), public evidence stops at ≤3B params, and by the Nested Learning paper's own statement the knowledge 'does not persist once the current context is removed'. They are long-context mechanisms, not cross-session continual learning.

### Cited Findings
- Titans (Ali Behrouz, Peilin Zhong, Vahab Mirrokni; Google; arXiv 2501.00663, 31 Dec 2024): a "neural long-term memory module that learns to memorize historical context"; attention = short-term memory, neural memory = "long-term, more persistent, memory"; three variants of combining memory with attention; claims to "effectively scale to larger than 2M context window size with higher accuracy in needle-in-haystack tasks compared to baselines". — [arXiv 2501.00663](https://arxiv.org/abs/2501.00663)
- Titans Revisited (Di Nepi, Siciliano, Silvestri; Sapienza; arXiv 2510.09551, Oct 2025): original Titans had no public code and "ambiguities in the original description hinder reproducibility"; reimplementation finds "Titans does not always outperform established baselines due to chunking. However, its Neural Memory component consistently improves performance compared to attention-only models" (tasks: masked LM, time-series, recommendation — small scale). — [arXiv 2510.09551](https://arxiv.org/abs/2510.09551)
- TTT-E2E "End-to-End Test-Time Training for Long Context" (Tandon, Dalal, Li, Koceja, Rød, Buchanan, Wang, Leskovec, Koyejo, Hashimoto, Guestrin, McCaleb, Choi, Yu Sun; Astera/NVIDIA/Stanford/Berkeley/UCSD; arXiv 2512.23675, 29 Dec 2025): frames long context "as a problem in continual learning": a standard Transformer with sliding-window attention "continues learning at test time via next-token prediction on the given context, compressing the context it reads into its weights"; initialization meta-learned (gradients of gradients) for post-TTT loss. "For 3B models trained with 164B tokens, our method (TTT-E2E) scales with context length in the same way as Transformer with full attention, while others, such as Mamba 2 and Gated DeltaNet, do not"; "constant inference latency regardless of context length, making it 2.7× faster than full attention for 128K context" (H100). Code public (github.com/test-time-training/e2e). Contrasts with dynamic evaluation (Mikolov 2013, Krause 2018) which is "TTT-naive". — [arXiv 2512.23675](https://arxiv.org/abs/2512.23675)
- TTT-E2E details: only the MLPs in the last 1/4 of blocks are updated at test time (760M model: "5× larger hidden state (88M vs. 18M)" than a multi-head all-layer variant, prefill latency 0.0086 vs 0.017 s per 1K tokens on H100); TTT mini-batch b=1K tokens, sliding window k=8K; models 125M–3B; pretrain DCLM at 8K, extend on Books up to 128K. Updating only 1 or 3 layers "does not scale with context length" like full attention; 6 or 12 do. — [arXiv 2512.23675](https://arxiv.org/abs/2512.23675)
- TTT-E2E NEEDLE-IN-HAYSTACK (RULER S-NIAH, 3B models at 128K): "Transformer with full attention dramatically outperforms the other methods, including ours, especially in long context… the key mechanism in our method is compression, which leaves out seemingly irrelevant details, such as the target string." I.e., weight-compressed context helps loss but loses verbatim recall. — [arXiv 2512.23675](https://arxiv.org/abs/2512.23675)
- TTT-E2E scaling caveat: advantage over full attention "visibly decreases with more training compute in the regime of small compute budget", stabilising beyond ~760M params / ~48B tokens; results sensitive to tokenizer and data (SlimPajama showed an uptick; DCLM/FineWebEdu did not). — [arXiv 2512.23675](https://arxiv.org/abs/2512.23675)
- TTT layers (Yu Sun, Xinhao Li, Karan Dalal et al.; arXiv 2407.04620, 5 Jul 2024): hidden state = a model (TTT-Linear / TTT-MLP) updated by a self-supervised gradient step on each test sequence; evaluated 125M–1.3B; "TTT-Linear and TTT-MLP can keep reducing perplexity by conditioning on more tokens, while Mamba cannot after 16k context"; "TTT-MLP still faces challenges in memory I/O". Code JAX + PyTorch public. — [arXiv 2407.04620](https://arxiv.org/abs/2407.04620)
- Titans setup & numbers (arXiv 2501.00663 v1): four scales 170M, 340M, 400M (15B FineWeb-Edu tokens) and 760M (30B tokens); 4K training length, Llama-2 tokenizer. At 760M/30B: Transformer++ Wiki ppl 25.21, avg acc 48.69; Gated DeltaNet 21.18 / 49.69; Samba* 20.63 / 51.08; Titans (LMM, memory only) 20.04 / 51.56; Titans (MAC)* 19.93 / 52.51; Titans (MAG)* 18.61 / 52.50. Memory update uses a "surprise" (gradient) with momentum and weight decay as forgetting gate; deep (multi-layer MLP) memory. S-NIAH evaluated only at 2K–16K. BABILong: Titans (MAC) "outperforms all baselines, including extremely large models, e.g., GPT4" in few-shot and fine-tuned setups (numbers only in figure); "even augmenting Llama3.1-8B with RAG performs worse than Titans with about ×70 less parameters". Paper states larger-model results were to come in a later version. — [arXiv 2501.00663](https://arxiv.org/abs/2501.00663)
- ATLAS (Behrouz, Li, Kacham, Daliri, Deng, Zhong, Razaviyayn, Mirrokni; Google; arXiv 2505.23735, 29 May 2025): diagnoses RNN/long-term memory failures as (1) limited capacity, (2) "online nature of update, i.e., optimizing the memory only with respect to the last input", (3) weak memory management; ATLAS optimizes memory over a sliding window of current+past tokens ("Omega rule"), plus DeepTransformers / Deep Omega Transformers (strict generalisations of softmax attention). Claim: "Atlas further improves the long context performance of Titans, achieving +80% accuracy in 10M context length of BABILong benchmark." — [arXiv 2505.23735](https://arxiv.org/abs/2505.23735)
- Nested Learning / HOPE (Behrouz, Razaviyayn, Zhong, Mirrokni; Google; NeurIPS 2025 version; arXiv 2512.24695, 31 Dec 2025; Google blog Nov 2025): model = nested multi-level optimisation problems each with own "context flow" and update frequency; optimizers (Adam, momentum) reinterpreted as associative memories; "Continuum Memory System" (CMS) = chain of MLP blocks each updated every C(ℓ) steps (Transformer = special case k=1, update frequency 0); HOPE = self-modifying (Titans-like) sequence model + CMS; also M3 optimizer (Adam+Muon+CMS) which "might suffer from computational overhead… when scaling to larger networks". — [arXiv 2512.24695](https://arxiv.org/abs/2512.24695); [Google Research blog](https://research.google/blog/introducing-nested-learning-a-new-ml-paradigm-for-continual-learning/)
- KEY PERSISTENCE QUOTE (Nested Learning paper itself): "The concepts commonly referred to as test-time training and test-time memorization are in fact instances of parametric in-context learning, where the acquired in-context knowledge does not persist once the current context is removed." and "the knowledge from that learning might not last or transfer to more persistent levels, mainly due to the lack of knowledge transfer between levels." In nested CMS the fast memory "re-initialized after the end of the context" to a meta-learned initial state. → Titans/ATLAS/TTT/Hope memories are per-sequence; nothing is written back to slow weights across sessions by default. — [arXiv 2512.24695](https://arxiv.org/abs/2512.24695)
- HOPE results (per Google blog & search summaries; paper experiments section truncated in mirror, numbers NOT verified): Hope "achieves lower perplexity and higher accuracy than state-of-the-art recurrent models or standard transformers on language modeling & common-sense reasoning" and "outperforms prior architectures like Titans, TTT, and Mamba2 on long-context needle-in-a-haystack tasks"; class-incremental text classification (CLINC, Banking, DBpedia) where "Hope architecture consistently outperforms other continual learning approaches" (figure cited in follow-up 2606.03979). — [Google Research blog](https://research.google/blog/introducing-nested-learning-a-new-ml-paradigm-for-continual-learning/); [arXiv 2606.03979](https://arxiv.org/abs/2606.03979)
- "Language Models Need Sleep: Learning to Self-Modify and Consolidate Memories" (arXiv 2606.03979, June 2026; builds on CMS/Nested Learning, authorship not captured): adds an offline "sleep" phase = memory consolidation modeled as distillation from the fast/small state into a larger model ("knowledge seeding"/"self-knowledge seeding") plus "dreaming" = SEAL-like self-modification; evaluates on SQuAD knowledge incorporation (single passage n=1 and CPT n=200 passages, 974 questions) claiming best results vs SEAL; ARC few-shot with Llama-3.2-1B; math reasoning with Qwen variants (claims better than SFT and GRPO); BABILong. Exact numbers were in images, not captured. — [arXiv 2606.03979](https://arxiv.org/abs/2606.03979)
- "Language Models Need Sleep" (different paper: Sangyun Lee, Sean McLeish, Tom Goldstein, Giulia Fanti; CMU/UMD; arXiv 2605.26099, May 2026): model "periodically converts recent context into persistent fast weights before clearing its key-value cache", N offline recurrent passes updating SSM fast weights via a learned local rule; tested on synthetic tasks (cellular automata, multi-hop graph retrieval) and a math reasoning task "on which a regular transformer as well as SSM-attention hybrid models fail"; longer sleep N → better, esp. deeper reasoning. Small-scale. — [arXiv 2605.26099](https://arxiv.org/abs/2605.26099)
- "Test-Time Training with KV Binding Is Secretly Linear Attention" (Junchen Liu, Sven Elflein, Or Litany, Zan Gojcic, Ruilong Li; affiliation not captured; arXiv 2602.21204, Feb 2026, ICML-format): "our analysis reveals multiple phenomena that contradict this memorization-based interpretation… a broad class of TTT architectures can be expressed as a form of learned linear attention operator"; reframes TTT "not as test-time memorization, but as learned linear attention with enhanced representational capacity"; enables fully parallel formulations. — [arXiv 2602.21204](https://arxiv.org/abs/2602.21204)
- Other 2025–26 TTT-for-long-context lines found (abstract-level only): LaCT "Test-Time Training Done Right" (arXiv 2505.23884, large-chunk TTT for hardware utilization/state capacity); PERK (arXiv 2507.06415, encode long context into a LoRA adapter via test-time gradient steps); Self-Guided TTT (arXiv 2607.09415, Jul 2026); E²-TTT (arXiv 2608.21308, Aug 2026, parallel chunk-level training preserving per-token dynamics); Gated Differentiable Working Memory (arXiv 2601.12906). — [HF papers index](https://huggingface.co/papers/2505.23884)

### Inferences (Q2)
- What these architectures "learn at test time" is a per-sequence associative map (keys→values or next-token predictor) stored in a fast-weight MLP/matrix; it is reset at sequence end. They are long-context/compression mechanisms, not cross-session continual learning. Google's own Nested Learning paper says so explicitly.
- Scale ceiling of published evidence: Titans ≤760M/30B tokens (v1), TTT layers ≤1.3B, TTT-E2E ≤3B/164B tokens; Hope sizes not verified. No frontier model (>10B) with a published test-time-trained memory has been documented in these sources.
- Consistent trade-off: compression into weights improves perplexity/latency but loses exact recall (TTT-E2E NIAH gap vs full attention); Titans' NIAH wins were only at ≤16K on small models, BABILong wins are fine-tuned-for-task.
- Independent scrutiny is mixed: Titans lacked official code and a reimplementation found it "does not always outperform" baselines; 2602.21204 argues TTT-KVB isn't really memorizing.

### Gaps (Q2)
- Hope/Nested Learning quantitative tables and model sizes not captured (HF mirror truncated; research.google blocked). Titans BABILong exact accuracies only in figures. ATLAS tables not read.
- No evidence found of any TTT/Titans-style model whose test-time-updated weights are persisted and reused across sessions/users in deployment.

## Q3. Self-updating models, knowledge injection, synthetic data, learning from experience

### Takeaway
Writing new knowledge into weights works only with heavy synthetic augmentation, meaning many diverse restatements per fact (EntiGraph: 1.3M→455M tokens lifts Llama-3-8B QuALITY 39.49%→56.22%; Active Reading: 66% SimpleQA-wiki; SEAL: 47.0% no-context SQuAD vs 46.3% with GPT-4.1 data; SDFT: 89% vs SFT 80%). Oracle RAG/ICL still usually matches or beats it on direct recall. Self-editing models (SEAL, SCoL, 'Sleep') are 1–7B research systems that still forget over sequential edits and are expensive per update.

### Cited Findings
- SEAL "Self-Adapting Language Models" (Adam Zweiger, Jyothish Pari, Han Guo, Ekin Akyürek, Yoon Kim, Pulkit Agrawal; MIT Improbable AI Lab; arXiv 2506.10943, June 2025): model generates "self-edits" (restated facts/implications, hyperparameters, augmentation tool calls) → SFT (LoRA in single-passage setting) → persistent weight update; RL outer loop (ReST-EM) rewards self-edits by downstream accuracy of the updated model. — [arXiv 2506.10943](https://arxiv.org/abs/2506.10943)
- SEAL knowledge incorporation (Qwen2.5-7B, no-context SQuAD): base 32.7%; finetune on raw passage 33.5%; base-model synthetic data 39.7%; GPT-4.1 synthetic implications 46.3%; SEAL after 2 RL rounds 47.0% ("outperforming using synthetic data from GPT-4.1"). CPT with n=200 passages: SEAL 58.2%, with GPT-4.1 synthetic data "slightly outperforming SEAL"; also run on full n=2067 SQuAD validation. — [arXiv 2506.10943](https://arxiv.org/abs/2506.10943)
- SEAL few-shot ARC (Llama-3.2-1B-Instruct; curated 11 train + 8 eval ARC tasks solvable by optimal TTT): adaptation success 72.5% vs 20% (base self-edits without RL) vs 0% (no adaptation), below Oracle TTT. — [arXiv 2506.10943](https://arxiv.org/abs/2506.10943)
- SEAL limitations (stated): sequential edits → "performance on earlier tasks gradually declines as the number of edits increases, suggesting that SEAL is still susceptible to catastrophic forgetting" (no retention objective); compute: "each self-edit evaluation takes approximately 30–45 seconds" (full finetune+eval per reward); assumes each context comes paired with a downstream evaluation task. — [arXiv 2506.10943](https://arxiv.org/abs/2506.10943)
- Cartridges (Sabri Eyuboglu, Ryan Ehrlich, Simran Arora, … James Zou, Azalia Mirhoseini, Christopher Ré; Stanford/Caltech/Buffalo; arXiv 2506.06266, June 2025): train a small KV cache offline per corpus (≈ prefix tuning) with frozen LLM; naive next-token training on the corpus "is not competitive with ICL"; SELF-STUDY = generate synthetic conversations about the corpus + context-distillation objective. Result: "match ICL performance while using 38.6× less memory and enabling 26.4× higher throughput"; extends effective context "from 128k to 484k tokens on MTOB"; Cartridges "can be composed at inference time without retraining". Motivation numbers: LLaMA 70B needs 84 GB for a 128k context; LLaMA 8B peak throughput drops 77× from 1k to 120k context on one H100. — [arXiv 2506.06266](https://arxiv.org/abs/2506.06266)
- Fine-Tuning or Retrieval? (Ovadia, Brief, Mishaeli, Elisha; Microsoft; arXiv 2312.05934, Dec 2023; EMNLP 2024): "while unsupervised fine-tuning offers some improvement, RAG consistently outperforms it, both for existing knowledge encountered during training and entirely new knowledge"; "LLMs struggle to learn new factual information through unsupervised fine-tuning, and… exposing them to numerous variations of the same fact during training could alleviate this problem." — [arXiv 2312.05934](https://arxiv.org/abs/2312.05934)
- Synthetic continued pretraining / EntiGraph (Zitong Yang, Neil Band, Shuangping Li, Emmanuel Candès, Tatsunori Hashimoto; Stanford; arXiv 2409.07431, Sep 2024; ICLR 2025): knowledge acquisition is data-inefficient ("models must be trained on hundreds to thousands of diverse representations" of a fact); EntiGraph extracts entities and generates text about entity relations; 1.3M real tokens (QuALITY books) → 455M synthetic tokens via gpt-4-turbo; continued pretraining of Llama 3 8B raises closed-book QuALITY QA "from 39.49% (Llama 3 8B Base) to 56.22%", log-linear in synthetic tokens; complementary to RAG (RAG on the EntiGraph-CPT model beats RAG on base). Limitation: generator may "hallucinate and fabricate non-existent relations". — [arXiv 2409.07431](https://arxiv.org/abs/2409.07431)
- Active Reading (Jessy Lin, Vincent-Pierre Berges, Xilun Chen, Wen-tau Yih, Gargi Ghosh, Barlas Oğuz; FAIR/Berkeley; arXiv 2508.09494, Aug 2025): model studies material with self-generated learning strategies; expert 8B models reach "66% on a Wikipedia-grounded subset of SimpleQA (+313% relative over vanilla finetuning) and 26% on FinanceBench (+160% relative)"; released "Meta WikiExpert-8B, a Wikipedia-expert model trained on 1 trillion generated tokens, which outcompetes models with hundreds of billions of parameters on factual QA". — [arXiv 2508.09494](https://arxiv.org/abs/2508.09494)
- Reversal curse (Berglund et al.; arXiv 2309.12288, Sep 2023; ICLR 2024): a model trained on "A is B" "will not automatically generalize to the reverse direction 'B is A'"; "robust across model sizes and model families and is not alleviated by data augmentation"; works in-context but not in-weights. Follow-up "Reverse Training to Nurse the Reversal Curse" (Golovneva, Allen-Zhu, Weston, Sukhbaatar; FAIR; arXiv 2403.13799, Mar 2024) trains on reversed strings as a fix. — [arXiv 2309.12288](https://arxiv.org/abs/2309.12288); [arXiv 2403.13799](https://arxiv.org/abs/2403.13799)
- Physics of Language Models 3.1 (Allen-Zhu & Li; arXiv 2309.14316): knowledge is linearly encoded/extractable "only possible with knowledge augmentations like permutation/rewriting of entity-attribute knowledge during pretraining. Without these augmentations, the language model can still memorize the training data, but… knowledge extraction via QAs quite hard, if not impossible"; recommends pretraining data rewriting (sentence shuffling, translation). — [arXiv 2309.14316](https://arxiv.org/abs/2309.14316)
- "Does Fine-Tuning LLMs on New Knowledge Encourage Hallucinations?" (Gekhman et al.; arXiv 2405.05904, May 2024; EMNLP 2024): categorises fine-tuning examples as Known/Unknown to the model; (from the paper) models learn Unknown examples slowly and, as they are learned, hallucination tendency increases — full-text numbers not re-extracted here. — [arXiv 2405.05904](https://arxiv.org/abs/2405.05904)
- Self-Distillation Fine-Tuning, SDFT (Idan Shenfeld, Mehul Damani, Jonas Hübotter, Pulkit Agrawal; MIT/ETH; arXiv 2601.19897, Jan 2026): on-policy learning from demonstrations by using the demonstration-conditioned model as its own teacher (in-context teacher, distil into weights). Qwen2.5-7B-Instruct: knowledge acquisition on ~200K tokens of post-cutoff 2025 articles — strict accuracy SFT 80% vs SDFT 89%, "nearly closes the gap to the oracle RAG model"; OOD (indirect) questions: SDFT "close to perfect", SFT low; continual pretraining "performs poorly"; forgetting measured as average over general benchmarks (e.g., Winogrande, HumanEval); sequential experiments: "a single model to accumulate multiple skills over time without performance regression". — [arXiv 2601.19897](https://arxiv.org/abs/2601.19897)
- Self-Consolidating Language Models, SCoL (Zekun Wang, Anant Gupta, Zihan Dong, Christopher J. MacLellan; Georgia Tech; arXiv 2605.07076, May 2026): LLM generates textual update instructions choosing which of its own Transformer layers to update when writing context into weights; trained with meta-RL over an evolving model state; SQuAD knowledge incorporation + LongBench v2 consolidation; improves acquisition and retention over prompting, summarization, batch TTT and sequential finetuning; learned selections are sparse and "align with layers of high Fisher information". — [arXiv 2605.07076](https://arxiv.org/abs/2605.07076)
- MEGa, "Memorization and Knowledge Injection in Gated LLMs" (arXiv 2504.21239, Apr 2025; injects each event memory into its own gated low-rank weights, activated at inference by query–context embedding matching): Llama-3.1-8B-Instruct sequentially fine-tuned on 50 fictional-character paragraphs and Wiki events: QA acc Fictional/Wiki — base 0.13/8.17; RAG 82.57/88.83; full FT 12.60/17.90 (MMLU 62.56→55.65); LoRA 0.80/0.53 (MMLU →47.94); full-batch (iid) 54.77/76.87; MEGa 72.53/78.03 with MMLU 61.75/61.99; iRAG (recall-then-answer) 80.67/84.70. Residual decline attributed to gating/retrieval failures. — [arXiv 2504.21239](https://arxiv.org/abs/2504.21239)
- Learning from experience framing: Silver & Sutton "Welcome to the Era of Experience" (2025 essay, preprint chapter): "any static procedure for synthetically generating data will quickly become outstripped… This can be achieved by allowing agents to learn continually from their own experience"; "Agents will inhabit streams of experience, rather than short snippets of interaction". (Position piece, no experiments.) — [Era of Experience (Silver & Sutton, 2025)](https://storage.googleapis.com/deepmind-media/Era-of-Experience%20/The%20Era%20of%20Experience%20Paper.pdf)
- CL-Bench (Parth Asawa, …, Matei Zaharia, Joseph E. Gonzalez; UC Berkeley/Snorkel/UW-Madison; arXiv 2606.05661, 4–5 Jun 2026): "the first difficult, expert-validated benchmark designed to measure whether LLM-based systems genuinely improve with experience" across 6 domains (software engineering, signal processing, outbreak forecasting, database querying, strategic games, demand forecasting) with a "gain metric to isolate learning from prior capabilities". Finding: frontier agents "frequently overfit to immediate observations or fail to reuse knowledge across instances, and dedicated memory systems do not fix this—in fact, naive ICL outperforms systems dedicated to memory management." — [arXiv 2606.05661](https://arxiv.org/abs/2606.05661)

### Inferences (Q3)
- The strongest in-weights knowledge-injection results in 2024–26 all depend on generating *diverse restatements* of each fact (EntiGraph 455M tokens from 1.3M; Active Reading 1T generated tokens for WikiExpert-8B; SEAL self-edits; SMF paraphrase batches; Cartridges self-study conversations; SDFT in-context teacher). This is the practical answer to the reversal curse / Physics-of-LMs finding that single-exposure facts are stored but not extractable. The price is a 100–1000× synthetic-token blow-up per fact and a generator-model dependency.
- RAG/ICL remains the ceiling on single-hop recall in most head-to-heads (Ovadia 2023; MEGa table: RAG 82.6/88.8 vs best in-weights 72.5/78.0; SDFT "nearly closes the gap to oracle RAG"); in-weights wins appear on indirect/OOD or multi-hop use of the knowledge (SDFT OOD, EntiGraph+RAG complementarity).
- Self-updating models (SEAL, SCoL, "Sleep") are 1B–7B, single-digit-to-hundreds of passages, and explicitly still forget over sequential edits; SEAL costs ~30–45 s of finetune+eval per candidate edit during meta-training.

### Gaps (Q3)
- Cartridges training compute per corpus (GPU-hours) not captured.
- Gekhman et al. exact numbers not re-extracted.
- No 2026 frontier-lab paper found that documents a deployed model updating its own weights from user interactions (as opposed to memory files/RAG).

## Q4. Forgetting mitigation in LLM continual pre-/post-training; best stability–plasticity trade-off at LLM scale

### Takeaway
Mitigation is regime-specific. For large-corpus continual pretraining, LR re-warm/re-decay plus 5–25% replay matches full retraining up to 10B. For skill post-training, on-policy RL and self-distillation forget much less than SFT at equal new-task gains; the forgetting tracks the KL shift on the new task (RL's Razor; RFT on Qwen2.5-VL-7B; SDFT). For small fact streams, sparse or isolated parameter updates (SMF memory slots; MEGa gated adapters) give the best measured retention, while LoRA 'learns less and forgets less' but still forgets badly in fact streams. No method yet shows high plasticity with near-zero forgetting on open-ended skill streams at >10B without replay.

### Cited Findings
- Continual pre-training recipe (Ibrahim, Thérien, Gupta, Richter, Anthony, Lesort, Belilovsky, Rish; arXiv 2403.08763, Mar 2024; TMLR): "a simple and scalable combination of learning rate (LR) re-warming, LR re-decaying, and replay of previous data is sufficient to match the performance of fully re-training from scratch on all available data"; shown at 405M (English→English, English→German shifts, hundreds of billions of tokens) and 10B parameters (weak shift); replay used: "5% replay for SlimPajama and 25% replay for German"; "using only a fraction of the compute". — [arXiv 2403.08763](https://arxiv.org/abs/2403.08763)
- LoRA Learns Less and Forgets Less (Biderman, Portes, Gonzalez Ortiz, Paul, Greengard, Jennings, King, Havens, Chiley, Frankle, Blakeney, Cunningham; Columbia/Databricks; arXiv 2405.09673, May 2024; TMLR 2024 Featured Cert.): Llama-2-7B; code & math; instruction FT (~100K pairs) and continued pretraining (~20B tokens; StarCoder-Python, OpenWebMath); "in the standard low-rank settings, LoRA substantially underperforms full finetuning. Nevertheless, LoRA better maintains the base model's performance on tasks outside the target domain"; in CPT "the performance gap… is not closed even with high ranks"; LoRA "mitigates forgetting more than common regularization techniques such as weight decay and dropout"; "full finetuning learns perturbations with a rank that is 10-100× greater than typical LoRA configurations". Forgetting measured on HellaSwag, WinoGrande, ARC-Challenge (MosaicML Gauntlet). — [arXiv 2405.09673](https://arxiv.org/abs/2405.09673)
- RL's Razor (Idan Shenfeld, Jyothish Pari, Pulkit Agrawal; MIT; arXiv 2509.04259, Sep 2025): "despite similar performance at a new task, RL preserves prior knowledge and capabilities significantly better"; "the degree of forgetting is determined by the distributional shift, measured as the KL-divergence between the fine-tuned and base policy evaluated on the new task"; "on-policy RL is implicitly biased towards KL-minimal solutions… whereas SFT can converge to distributions arbitrarily far from the base model"; forgetting–KL quadratic fit R²=0.96 (toy ParityMNIST setting) and curves coincide across SFT labelings; LLM experiments on Qwen 2.5 3B-Instruct (math/Open-Reasoner-Zero, science Q&A/SciKnowEval Chemistry, tool use/ToolAlpaca) plus a robotics foundation model. — [arXiv 2509.04259](https://arxiv.org/abs/2509.04259)
- RFT naturally mitigates forgetting (Song Lai et al.; CAS/CityU; arXiv 2507.05386, Jul 2025, v5 Jan 2026): Qwen2.5-VL-7B-Instruct over seven sequential multimodal tasks — "SFT leads to catastrophic forgetting of previously learned tasks. In contrast, RFT inherently preserves prior knowledge and achieve performance comparable to multi-task training"; RFT "protects and even enhances" MMMU and MMLU-Pro while "SFT degrades general model capabilities severely"; mechanism attributed not to KL penalty or CoT but to implicit regularization — "RFT's gradient updates are naturally scaled by the reward variance". — [arXiv 2507.05386](https://arxiv.org/abs/2507.05386)
- SDFT (arXiv 2601.19897, Jan 2026) extends RL's-Razor logic to demonstrations: on-policy self-distillation "consistently outperforms SFT, achieving higher new-task accuracy while substantially reducing catastrophic forgetting"; sequential multi-skill accumulation "without performance regression" (Qwen2.5-7B-Instruct). — [arXiv 2601.19897](https://arxiv.org/abs/2601.19897)
- O-LoRA (Xiao Wang et al.; Fudan; arXiv 2310.14152, Oct 2023; EMNLP 2023 Findings): learns each task in low-rank subspaces kept orthogonal to previous tasks' LoRA subspaces; "marginal additional parameter costs and requires no user data storage for replay"; outperforms prior SOTA on standard CL benchmarks (T5/LLaMA-scale task-incremental classification benchmarks). — [arXiv 2310.14152](https://arxiv.org/abs/2310.14152)
- Spurious forgetting (Junhao Zheng, Xidi Cai, Shengjie Qiu, Qianli Ma; SCUT; arXiv 2501.13453; ICLR 2025): many LLM "forgetting" drops "reflect a decline in task alignment rather than knowledge loss"; early optimization steps on a new task disrupt prior task alignment via orthogonal weight updates; freezing bottom layers gives "substantial improvements in four continual learning scenarios"; cites safety alignment undone by as few as ten identity-shift examples (Qi et al. 2024). — [arXiv 2501.13453](https://arxiv.org/abs/2501.13453)
- Sparse memory finetuning (see Q1): at matched TriviaQA fact acquisition, NQ F1 drops 11% (SMF) vs 71% (LoRA) vs 89% (full FT) on a 1.3B memory-layer model; Pareto-dominant across sweeps. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- MEGa gated LoRA memories (see Q3): Llama-3.1-8B, 50 sequential memories: MMLU stays 61.75–61.99 (base 62.56) vs full FT 55.65–56.28 and LoRA 46.88–47.94, while QA reaches 72.5–78.0%. — [arXiv 2504.21239](https://arxiv.org/abs/2504.21239)
- Other constrained-update methods found (abstract level only): "Sculpting Subspaces: Constrained Full Fine-Tuning in LLMs for Continual Learning" (adaptive SVD, arXiv 2504.07097, Apr 2025); "Forget Forgetting: Continual Learning in a World of Abundant Memory" (arXiv 2502.07274; rank-based parameter resets + weight averaging; argues compute, not memory, is the binding constraint). — [HF papers: 2504.07097](https://huggingface.co/papers/2504.07097); [HF papers: 2502.07274](https://huggingface.co/papers/2502.07274)

### Inferences (Q4)
- Best-evidenced stability–plasticity trade-offs at LLM scale, by regime: (a) large-corpus continual pretraining: LR re-warm/re-decay + ~5–25% replay matches full retraining up to 10B params — effectively "solved" when you have the old data and can afford large runs; (b) skill post-training: on-policy RL / on-policy self-distillation forgets far less than SFT at matched new-task performance (3B–7B evidence), with forgetting predicted by forward KL on the new task; (c) small-data fact streams: sparse memory-slot updates (1.3B) and gated/isolated adapters (8B) give the best measured retention, but LoRA alone does not (71% NQ drop in SMF's setting; LoRA MMLU drop ~62.6→~47.9 in MEGa's setting).
- No single method has been shown to give high plasticity AND near-zero forgetting on an open-ended stream (facts + skills) at >10B scale without replay.
- The field's forgetting metrics are heterogeneous (NQ F1 relative drop, MMLU delta, "normalized to peak"), so cross-paper comparisons are approximate.

### Gaps (Q4)
- Model-merging-for-CL numbers at LLM scale (e.g., MagMax, TIES-style sequential merging) not collected in this pass.
- No head-to-head of SMF vs RL-style on-policy updates vs replay on the same benchmark was found.

## Q5. On-device / efficient learning into weights (phones, edge), 2024–2026

### Takeaway
On-device learning into LLM weights is at the feasibility-demo stage. Zeroth-order fine-tuning of OPT-1.3B uses ~6.5 GB on a phone (PocketLLM, 2024). MobileFineTuner (Dec 2025) runs full-FT/LoRA for ≤1B models on a Pixel 8 Pro at roughly 5–10 minutes per step with battery-aware throttling. Qualcomm (Jun 2026) cuts LoRA peak memory for Llama-3.2-3B from 40.41 GB to 1.59 GB at 4K tokens. None of these works couple on-device updates with forgetting control, and none report energy per learned fact.

### Cited Findings
- PocketLLM (arXiv 2407.01031; ACL PrivateNLP 2024 workshop; affiliation not verified): derivative-free (MeZO zeroth-order) on-device fine-tuning; "RoBERTa-large model and OPT-1.3B can be fine-tuned locally on the OPPO Reno 6 smartphone using around 4GB and 6.5GB of memory respectively". — [ACL Anthology](https://aclanthology.org/2024.privatenlp-1.10/)
- MobiLLM (arXiv 2502.20421, Feb 2025): server-assisted side-tuning — phone keeps a frozen backbone while "offloading the memory and computation-intensive backpropagation of a trainable side-network to a high-performance server"; "up to 4× memory reduction" vs baselines. (Not purely on-device.) — [arXiv 2502.20421](https://arxiv.org/abs/2502.20421)
- MobileFineTuner (arXiv 2512.08211, Dec 2025; open-source C++): full-FT and LoRA on commodity phones with memory-efficient attention, activation checkpointing, gradient accumulation, parameter sharding, energy-aware scheduling; models GPT2-124M/355M, Qwen2.5-0.5B, Gemma3-270M, Gemma3-1B; "typical mobile phones in 2025 are equipped with only 4-16 GB of RAM"; on a Pixel 8 Pro, when battery fell below 60% (~step 53, ~4 h in), step time was throttled from 0.081 to 0.164 hour/step — i.e., ~5–10 minutes per optimizer step for these small models. (Search-snippet level; full text blocked.) — [arXiv 2512.08211](https://arxiv.org/abs/2512.08211); [GitHub MobileFineTuner](https://github.com/king21-noass/MobileFineTuner)
- Qualcomm AI Research "Techniques for Peak Memory Reduction for LoRA Fine-tuning of LLMs on Edge Devices" (Hassan Dbouk et al.; arXiv 2606.19528, 17 Jun 2026): INT4 base + on-the-fly dequant, selective activation caching + disk offload, top-k softmax approximation, logits masking; "at 4K tokens, the FP32 LoRA baseline for Llama-3.2 3B requires 40.41 GB, while the optimized configuration… reduces peak memory to just 1.59 GB, a reduction of over 25×"; "fine-tuning at 16K token lengths with only 6.95 GB"; on a 2025 flagship phone with 12 GB RAM, peak memory reduced "to 7.38% of the unoptimized baseline at 32 tokens, and to 19.37% at 2048 tokens". (Search-snippet level.) — [arXiv 2606.19528](https://arxiv.org/abs/2606.19528)
- Qualcomm "Stepping Forward on the Last Mile" (Chen Feng et al.; arXiv 2411.04036, Nov 2024): fixed-point forward gradients (two forward passes, no backprop) for on-device training because most NPUs/DSPs/MCUs "are designed as fixed-point inference accelerators, without training capabilities"; vision/audio benchmarks; concludes feasible for "last mile" customization. — [arXiv 2411.04036](https://arxiv.org/abs/2411.04036)
- ElasticZO (Sugiura & Matsutani; Keio; arXiv 2501.04287, Jan 2025): hybrid — backprop only for last few layers, ZO for the rest; ElasticZO-INT8 "achieves integer arithmetic-only ZO-based training for the first time" (classification DNNs, not LLMs). — [arXiv 2501.04287](https://arxiv.org/abs/2501.04287)
- Related 2026 titles (abstract-level): "Parameter Efficiency Is Not Memory Efficiency: Rethinking Fine-Tuning for On-Device LLM Adaptation" (arXiv 2604.22783); MemLoRA "Distilling Expert Adapters for On-Device Memory Systems" (arXiv 2512.04763); AGZO activation-guided ZO fine-tuning (arXiv 2601.17261). — [arXiv 2604.22783](https://arxiv.org/abs/2604.22783); [HF 2512.04763](https://huggingface.co/papers/2512.04763)

### Inferences (Q5)
- As of 2026, on-device learning-into-weights has been demonstrated only for ≤3B models, typically LoRA or ZO, at minutes-per-step speeds and multi-GB peak memory; no published work combines on-device updates with a forgetting-controlled continual-learning method (e.g., SMF or gated adapters) or measures forgetting on-device.
- Hardware mismatch (inference-only fixed-point NPUs) pushes toward forward-only (ZO / forward-gradient) or split (server-assisted) training, which learn far less per sample than backprop.

### Gaps (Q5)
- No measured Joules-per-update or battery-% per fact learned on a phone for an LLM was found. Apple/Google production on-device personalization of LLM weights: no primary-source evidence found (Apple adapters appear to be trained server-side — not verified).

## Q6. Open problems (explicit in surveys + synthesized from 2025–2026 evidence)

### Takeaway
The surveys explicitly list theory of forgetting in LLMs, efficient replay, controllable/rollback-able memory, and per-user preference trade-offs as open. The 2025–26 evidence adds: skill (not fact) continual learning at scale; single-exposure sample efficiency; consolidating test-time fast weights into persistent weights; exact recall vs compression; reproducible, open memory-layer models; principled parameter selection; and realistic evaluation. CL-Bench (Jun 2026) finds frontier agents barely improve from experience, and memory systems lose to naive ICL.

### Cited Findings
- Shi et al., "Continual Learning of Large Language Models: A Comprehensive Survey" (arXiv 2404.16789, Apr 2024; ACM CSUR) — prospective directions stated: (1) "Theories of Continual LLMs": "a notable gap in research focusing on continually learning LLMs with robust theoretical guarantees and understanding the forgetting behaviors of LLMs from a theoretical perspective"; (2) "Efficient Replay for Knowledge Retention": "More sophisticated and accurate data mixing strategies and efficient replay sample selection mechanisms are needed"; (3) "Continual LLMs with Controllable Memory": parametric memory "lacks interpretability and explicit manipulability", needed for unlearning/rollback; (4) "Continual LLMs with Custom Preferences" (per-user Pareto trade-offs); also: the challenge "shifts from storage efficiency to computational efficiency" when data can be retained, while vendors don't release training data so downstream users must do rehearsal-free CL. — [arXiv 2404.16789](https://arxiv.org/abs/2404.16789)
- SMF authors: need to go "beyond fact learning" (reasoning, coding) and to "larger models"; "It's unclear how RAG would be a suitable solution on tasks like reasoning and coding where retrieval is difficult. We'd like models to distill the learnings from mistakes, feedback, and reasoning chains". — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Memory Layers at Scale: production efficiency of memory layers is an open "substantial engineering task". — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Nested Learning: test-time memory "does not persist once the current context is removed" — knowledge transfer from fast to slow levels is the missing piece. — [arXiv 2512.24695](https://arxiv.org/abs/2512.24695)
- TTT-E2E: compression into weights loses needle-level recall ("full attention dramatically outperforms… including ours"); suggests "TTT on self-generated tokens" as future work. — [arXiv 2512.23675](https://arxiv.org/abs/2512.23675)
- SEAL: forgetting under sequential self-edits; expensive reward (30–45 s per edit eval); needs paired evaluation tasks for each context. — [arXiv 2506.10943](https://arxiv.org/abs/2506.10943)
- CL-Bench (Jun 2026): frontier systems "leave headroom", "overfit to immediate observations or fail to reuse knowledge across instances", and memory systems lose to naive ICL — i.e., even non-parametric continual learning is unsolved in agentic settings. — [arXiv 2606.05661](https://arxiv.org/abs/2606.05661)
- Reversal curse / knowledge extraction: facts learned in one direction/format are not usable in others without augmentation. — [arXiv 2309.12288](https://arxiv.org/abs/2309.12288); [arXiv 2309.14316](https://arxiv.org/abs/2309.14316)

### Inferences — list of problems no method has solved as of Sep 2026 (synthesis; each grounded in findings above)
1. Continual learning of SKILLS (not facts) into weights from small, non-iid streams without replay, at >10B scale, with measured near-zero forgetting — every low-forgetting result is facts-only (SMF, MEGa, SDFT knowledge) or 3–7B skill post-training (RL's Razor, RFT, SDFT).
2. Sample-efficient single-exposure fact learning: all working recipes need tens–thousands of synthetic paraphrases per fact (EntiGraph ~350× token blow-up; Active Reading 1T tokens) and a strong generator; reversal/extraction failures persist without augmentation.
3. Persistence of test-time memory: TTT/Titans/ATLAS/Hope reset at context end; no demonstrated mechanism to consolidate fast weights into slow weights across sessions at scale without forgetting ("sleep"/consolidation papers are small-scale, 2026).
4. Lossless recall vs compression: in-weights/fast-weight compression trails full attention and RAG on exact retrieval (TTT-E2E NIAH; MEGa vs RAG; SDFT vs oracle RAG).
5. Scale & reproducibility: SMF evidence is 1.3B (+0.5B retrofits); no public pretrained memory-layer LLM weights; Titans lacked official code; Hope numbers not independently reproduced.
6. Principled slot/parameter selection: TF-IDF → KL scoring → Fisher-aligned layer selection (SCoL) are heuristics; no theory guarantees non-interference (survey's "theories of continual LLMs" gap).
7. Controllable/auditable memory: cannot reliably roll back, unlearn, or inspect what was written into weights (survey "controllable memory"; spurious-forgetting shows alignment can be undone by ~10 examples).
8. Evaluation: no agreed benchmark measuring long-horizon in-weights learning+forgetting jointly; CL-Bench (2026) shows current systems barely learn from experience even non-parametrically.
9. Cost: per-update compute for self-editing (SEAL 30–45 s/eval), meta-learned TTT (gradients-of-gradients), synthetic-data generation, and on-device training (minutes/step, GBs of RAM on ≤3B models) all remain far from "learn as you go" economics.
10. Optimizer/state interaction: Adam momentum/weight-decay interacts badly with sparse updates (SMF used SGD); Nested Learning notes optimizer state is discarded at "end of pretraining" — no standard continual optimizer.

### Gaps (Q6)
- 2025–2026 surveys (e.g., "A Comprehensive Survey on Continual Learning in Generative Models", arXiv 2506.13045; "Lifelong Learning of LLM based Agents: A Roadmap", arXiv 2501.07278) were located but their explicit future-directions sections were not read in full here.
