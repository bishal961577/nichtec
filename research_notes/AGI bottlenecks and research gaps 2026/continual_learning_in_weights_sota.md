### Cited Findings

#### Sparse Memory Finetuning (SMF) — Jessy Lin et al. (full author list not captured from mirror; FAIR at Meta + UC Berkeley); arXiv 2510.15103 (v1 dated 16 Oct 2025, posted 20 Oct 2025)
- Headline: "while NaturalQuestions F1 drops by 89% after full finetuning on new facts and 71% with LoRA, sparse memory finetuning yields only an 11% drop with the same level of new knowledge acquisition" (setting: learning a stream of 1K TriviaQA facts; held-out = NaturalQuestions F1) — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Mechanism: memory layer replaces ONE FFN in the middle of the transformer (layer 12 of 22) with a product-key lookup into a pool of 1M slots, k=32 accesses per token, 4 memory heads, value dim 1024 → "32∗1024=32,768 active parameters in this layer instead of 50M parameters in original FFN (model dim 2048, FFN dim 2048∗4)". Output = (y ⊙ silu(xᵀW1))ᵀW2 input-dependent gating; keys/values are trainable parameters. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Base model: 1.3B-parameter model pretrained from scratch (same data for all methods); batch size 64; seq len 64 (TriviaQA) / 512 (SimpleQA). — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- HOW SLOTS ARE CHOSEN: per batch, count all memory-index accesses; rank each slot with TF-IDF where TF = the slot's share of accesses in the current batch and IDF = log((|B|+1)/(#background batches in which slot is accessed +1)); background B = memory accesses on 1000 random batches of DCLM (proxy for pretraining data). "These 'background indices' do not change during finetuning and can be stored statically in the model checkpoint." Only the VALUES of the top-t slots receive gradient (stop-gradient on all other memory params); all accessed slots still contribute to the forward pass. Ranking is batch-level, so no task-boundary assumption. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- So: slot choice = "TF-IDF relative to pretraining usage" — both notions in the question are the same mechanism (TF = access in the new batch; IDF = rarity of access on pretraining/DCLM background). — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- t values: t=500 sufficient for fact learning; t=10,000 for document QA. Each forward pass accesses 10^3–10^6 indices (k × heads × batch × seqlen). Sweep t ∈ {25,50,100,200,500,1000}, lr ∈ {0.1, 2}; main results report lr=5 (high) and lr=2 (low). — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Optimizer matters: SGD used for SMF; AdamW (λ=0.1) best for full-FT and LoRA baselines; authors note Adam's adaptive per-parameter steps, weight decay and momentum "interact with sparsity in unexpected ways"; switching to SGD reduced SMF forgetting further but did not help FT/LoRA. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- What was learned: (1) Fact learning: 1K TriviaQA test questions rephrased as statements, each fact's batch filled with N paraphrases, one immediate gradient step per fact, in sequence; held-out = NaturalQuestions F1, HellaSwag acc, GSM8K NLL. (2) Document QA: 100 Wikipedia-grounded SimpleQA questions → cited Wikipedia docs split into 1,824 paragraph chunks, streamed one chunk at a time, each batch = N "Active Reading" synthetic augmentations of the same chunk. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Ablations: naive finetuning of all accessed memory values still causes catastrophic forgetting; full-finetuning the memory model (lr 5e-6) → final GSM8K NLL 3.87 (outlier); TF-only ranking learns comparably but forgets more, gap wider at t=50; using TriviaQA itself as background → more forgetting; NQ as background ≈ DCLM. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Mechanistic analysis: "core set" (indices shared by all paraphrases and the question) typically 100–500 indices; trainable indices align with core set and "often align with entity boundaries". — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Pareto sweep: full-FT lr {2e-6,5e-6,2e-5,5e-5} (lr >5e-6 "break" the model); LoRA rank {32,128,256}, alpha {½,1,2,4}×rank, lr {2e-4,5e-5,5e-6}; "sparse memory finetuning indeed Pareto dominates, learning more while forgetting less." — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)
- Stated limitations/future work: tested only on factual learning "for which RAG is a natural present-day solution"; need "to scale our results to more complex tasks beyond fact learning, as well as larger models"; better slot-selection (input-dependent t, other reranking criteria); optimizer choice for CL unexplored. — [arXiv 2510.15103](https://arxiv.org/abs/2510.15103)


#### Memory Layers at Scale — Vincent-Pierre Berges, Barlas Oğuz, Daniel Haziza, Wen-tau Yih, Luke Zettlemoyer, Gargi Ghosh (Meta FAIR); arXiv 2412.09764 (v2 dated 20 Dec 2024)
- Design: trainable key-value lookup replacing the FFN of one or more transformer layers; trainable product-quantized keys (Lample et al. 2019: two half-key sets of size √N, top-k over the product); shared memory pool across all memory layers; "Memory+" = 3 memory layers (centred, stride 4 for 134m, 8 for others), swilu/silu input-dependent gating output=(y⊙silu(xᵀW1))ᵀW2, key dim = half value dim; qk-norm for stability. — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Systems: memory values sharded across embedding dim across GPUs; custom CUDA EmbeddingBag kernels reach "3TB/s of memory bandwidth, close to H100 spec 3.35TB/s (vs <400GB/s with PyTorch)"; "end-to-end 6x faster compared to PyTorch's EmbeddingBag". Memory layers are "almost entirely memory bandwidth bound". — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Scale: base models 134M, 373M, 720M, 1.3B (Llama2 tokenizer, trained to 1T tokens) and 8B (Llama3 config); memory up to 64M keys = "128B memory parameters"; 8B base + 4096² (=16M) memory values = 64B extra params trained to 200B and 1T tokens. — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Results (Table 1, 1M memory values unless noted; NQ accuracy / TQA F1): 1.3B dense 7.76 / 32.64; 1.3B Memory 9.83 / 39.47; 1.3B Memory+ (3.377B total) 13.68 / 42.89; Memory+ 4M (9.823B total) 14.43 / 51.18; Memory+ 16M (35.618B) 20.14 / 58.67; Memory+ 64M (138.748B total) 20.78 / 62.14; vs Llama2 7B (2T tokens) 25.10 / 64.00. MOE at 1.3B (3.545B total) 8.14 / 31.46 — MoE "underperform[s] the memory variants by large margins". — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Claims: memory models "outperform dense models with more than twice the computation budget"; "improve factual accuracy... by over 100%"; 1.3B with 64M keys "approaches the performance of the Llama2 7B model, trained on 2x more tokens using 10x more FLOPs"; at 8B, "At only 1 trillion tokens of training, our Memory+ model approaches the performance of Llama3.1 8B, which was trained on 15 trillion tokens" (8B table numbers were rendered as image in mirror – not captured). Gains larger early in training (200B tokens) → "memory helps models learn facts faster". — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Ablations: ~3 memory layers is the sweet spot (more replaces too many dense FFNs, degrading); value dim = model dim optimal. — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)
- Stated shortcomings: "substantial engineering task to make them efficient enough for large scale production uses"; only "high level empirical evidence" on factuality (short-form QA only; long-form left to future work); hopes sparse updates enable "less forgetting, fewer hallucinations, and continual learning" (i.e. CL was not tested in this paper). — [arXiv 2412.09764](https://arxiv.org/abs/2412.09764)

#### 2026 follow-ups on sparse memory finetuning (full text NOT readable here — arXiv/bytez/pith/awesomepapers blocked by proxy; details below are from search-engine abstracts/snippets only, flag as partially verified)
- "Improving Sparse Memory Finetuning" — Satyam Goyal, Anirudh Kanchi, Garv Shah, Prakhar Gupta; arXiv 2604.05248, submitted 6 Apr 2026. Contributions per abstract: (1) open-source "retrofitting" pipeline that surgically replaces FFNs in a pretrained Qwen-2.5-0.5B with sparse key-value memory layers followed by a "healing" stage to recover general capability; (2) critiques TF-IDF and proposes a KL-divergence slot-scoring rule "based on the information gain of the current batch relative to a background usage distribution" (prioritising "informationally 'surprising'" slots); (3) retrofitted models learn TriviaQA via sparse updates "while maintaining higher stability on held-out benchmarks (GSM8k, NaturalQuestions) compared to dense finetuning". Exact numbers not obtained. — [arXiv 2604.05248](https://arxiv.org/abs/2604.05248)
- "Sparse Memory Finetuning as a Low-Forgetting Alternative to LoRA and Full Finetuning" — arXiv 2605.03229 (v2 exists; search snippets date it to May/June 2026; Prakhar Gupta among authors). Re-implements SMF on Qwen-2.5-0.5B-Instruct; task = MedMCQA (4-choice medical exam); forgetting probes = WikiText perplexity and TriviaQA accuracy. "SMF improves MedMCQA by 2.5 percentage points while keeping both forgetting probes within roughly 1 point of the base model, whereas LoRA and full finetuning achieve larger gains but with clear drift on both." Compares KL-divergence vs TF-IDF row selection, which "balance the two forgetting metrics differently". — [arXiv 2605.03229](https://arxiv.org/abs/2605.03229)
- Note: both follow-ups are small-scale (0.5B) academic replications; they illustrate SMF's main weakness: lower plasticity on a skill-like task (MedMCQA +2.5 pp, less than LoRA/full FT). — inference from [arXiv 2605.03229](https://arxiv.org/abs/2605.03229)

### Inferences (Q1)
- SMF is the cleanest published evidence (as of Sep 2026) that *where* you write matters more than *how much* you write: the same learning on TriviaQA facts with ~11% vs 71–89% held-out degradation. But the evidence is (a) at 1.3B scale, (b) on fact recall only, (c) on a model pretrained from scratch with a memory layer — no frontier-scale memory-layer model with public weights exists, so replication has been at 0.5B via retrofitting.
- The TF-IDF IDF term is essentially a cheap, static "importance" prior (akin to a sparse, binary EWC/Fisher mask computed on pretraining data). 2026 follow-ups replace it with KL/information-gain scoring; no follow-up has yet demonstrated SMF on skills (coding, reasoning) at scale.

### Gaps (Q1)
- Exact numbers of the 2026 SMF follow-ups (2604.05248, 2605.03229) could not be read (arXiv, bytez, pith, awesomepapers, lacuna, openreview blocked; not on HF papers mirror). Only abstract-level claims recorded.

### Cited Findings
- Titans (Ali Behrouz, Peilin Zhong, Vahab Mirrokni; Google; arXiv 2501.00663, 31 Dec 2024): a "neural long-term memory module that learns to memorize historical context"; attention = short-term memory, neural memory = "long-term, more persistent, memory"; three variants of combining memory with attention; claims to "effectively scale to larger than 2M context window size with higher accuracy in needle-in-haystack tasks compared to baselines". — [arXiv 2501.00663](https://arxiv.org/abs/2501.00663)
- Titans Revisited (Di Nepi, Siciliano, Silvestri; Sapienza; arXiv 2510.09551, Oct 2025): original Titans had no public code and "ambiguities in the original description hinder reproducibility"; reimplementation finds "Titans does not always outperform established baselines due to chunking. However, its Neural Memory component consistently improves performance compared to attention-only models" (tasks: masked LM, time-series, recommendation — small scale). — [arXiv 2510.09551](https://arxiv.org/abs/2510.09551)
- TTT-E2E "End-to-End Test-Time Training for Long Context" (Tandon, Dalal, Li, Koceja, Rød, Buchanan, Wang, Leskovec, Koyejo, Hashimoto, Guestrin, McCaleb, Choi, Yu Sun; Astera/NVIDIA/Stanford/Berkeley/UCSD; arXiv 2512.23675, 29 Dec 2025): frames long context "as a problem in continual learning": a standard Transformer with sliding-window attention "continues learning at test time via next-token prediction on the given context, compressing the context it reads into its weights"; initialization meta-learned (gradients of gradients) for post-TTT loss. "For 3B models trained with 164B tokens, our method (TTT-E2E) scales with context length in the same way as Transformer with full attention, while others, such as Mamba 2 and Gated DeltaNet, do not"; "constant inference latency regardless of context length, making it 2.7× faster than full attention for 128K context" (H100). Code public (github.com/test-time-training/e2e). Contrasts with dynamic evaluation (Mikolov 2013, Krause 2018) which is "TTT-naive". — [arXiv 2512.23675](https://arxiv.org/abs/2512.23675)
